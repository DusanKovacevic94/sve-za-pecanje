# 083 — Private CMS social preview and download

Status: done
Priority: P2

## Goal

Give editors a preview of the exact generated social image and a JPEG download,
entirely within the authenticated CMS.

## Work

- [x] Add a Social preview panel/action to the post editor with effective copy,
  generation progress, clear errors, preview, and `Preuzmi sliku` download control.
  Explain that the artwork is intended for both Instagram and Facebook and that
  downloading does not publish or schedule a post.
- [x] Define and implement unsaved-edit behavior explicitly: either preview the current
  authorized form values, or require a saved draft with a clear prompt. Never silently
  show an older saved render as if it includes pending edits.
- [x] Add an authenticated, editor-authorized render endpoint with bounded input,
  same-origin/CSRF protection as appropriate, request limits, and `private, no-store`
  response policy. Check access to the target post; no public draft-preview URL.
- [x] Use the same generated bytes for displayed preview and JPEG download. Mark the
  preview stale when relevant fields change and prevent downloading an outdated image
  as current. Handle concurrent requests so older responses cannot replace newer ones.
- [x] Provide accessible control labels, keyboard interaction, preview text alternative,
  and responsive layout. Do not fire public analytics for draft preview/render actions.
- [x] Keep output private and ephemeral. Avoid uploading generated draft text into the
  existing public-media storage; revoke browser object URLs and clean temporary data.

## Acceptance criteria

- An editor can prepare a draft, adjust social copy, preview, and download a matching
  1080 × 1350 JPEG without publishing the article or contacting Meta.
- Unauthorized, cross-origin, oversized, and invalid render requests fail safely.
- Loading/error/retry, stale renders, long text, and unsaved edits behave predictably;
  failure does not block the existing article publish workflow.
- No Meta app, token, public object upload, new scheduler, or social publication hook
  is introduced. Public asset hosting remains a future integration concern.

## Primary files

`cms/src/` (admin component and endpoint), `cms/src/collections/Posts.ts`,

## Implementation and verification — 2026-09-08

- Native Payload UI field with effective copy, Serbian guidance, live progress/error
  messages, private image and `Preuzmi sliku`. Existing drafts use current form values,
  including unsaved edits; new articles must first be saved. No render saves the form.
- Shared browser/server fallback helper. Any title/excerpt/override change remounts
  the panel, aborts pending work, revokes its blob and removes download access until
  regeneration. Older responses cannot replace a newer image. Blob ownership begins
  before the React state commit, so immediate unmount also cleans it up.
- `POST /api/social-preview/:id` checks editor/admin and target-post read access,
  exact CMS Origin, Fetch Metadata and JSON. Actual body limit 4096 bytes/three seconds;
  six requests per editor and sixty total per minute per process, plus existing worker
  concurrency/deadline limits. Every handled result is private/non-cacheable. Scaling
  across processes requires shared rate coordination; see `cms/SOCIAL_CARD_RENDERER.md`.
- CMS lint/types, production build and all 23 unit tests passed. Full isolated
  PostgreSQL/MinIO/Mailpit integration passed, including real private JPEG responses,
  request limits and existing public blog/SEO/marketplace behavior. The editor browser
  journey passed again against the final build after tightening blob cleanup.
- Browser checks prove preview/download byte identity, unsaved copy with autosave
  blocked, stale URL revocation, delayed response isolation, overflow/retry, mobile
  layout and keyboard download. Public blog units (4), managed brand checks and
  Brand Manager validation passed.
- Added pinned direct `@payloadcms/ui` dependency and regenerated the import map/types.
  No new DB migration, managed asset changes, Meta credentials, services, public upload,
  analytics, deployment or production access. The 082 migration remains a prerequisite.
- Updated API/render/editor docs. Formal review and synthetic desktop/phone evidence:
  `../sve-za-pecanje-brand-manager/work/reviews/2026-09-08-cms-social-preview.md`.
